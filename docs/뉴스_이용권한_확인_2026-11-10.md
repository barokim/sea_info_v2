## 개별 이용 조건 확인 후 로컬 미리보기에 등록한 기사

아래 두 원문은 각각 **텍스트에 한하여 공공누리 제1유형**이라고 명시한다. 사진·이미지·첨부파일은 이용 대상에서 제외했다. 요약은 담당자가 작성했고 AI가 자동 생성하지 않았다.

| 기사 | 발행일 | 원문과 허락 표시 |
| --- | --- | --- |
| 한국의 갯벌, 세계유산 확대 등재 권고 | 2026-06-05 | [정책브리핑 원문](https://www.korea.kr/news/policyNewsView.do?newsId=148965977) |
| 고수온 피해 양식 어가에 1차 재난 지원금 | 2026-09-20 | [정책브리핑 원문](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156782514) |

`jobs/load_reviewed_news_preview.py`는 이 두 건을 `data/preview_local/sea_info_preview.db`에 등록했다. 이는 담당 작업 폴더에 별도로 만든 미리보기 DB이며 팀 공동 DB에는 반영하지 않았다.

## 이번 적용

- 담당 파일 `views/news.py`에서 시연용 기사(`example.com`/`예시` 출처)를 실제 수집 결과 목록에서 제외하고 현재 상태를 명시했다.
- 담당 파일의 수집기는 기존 권리 차단 설정을 유지한다. 권한이 확인되지 않은 출처를 승인 환경변수에 넣거나 실제 뉴스 DB에 저장하지 않았다.
- 정책브리핑 해수부 목록에 대한 기사별 권리 확인 수집기와 담당 PC 오전 6시 예약 작업을 아래와 같이 추가했다.

## 정책브리핑 해수부 자동 수집 — 2026-11-10

**새 담당 파일:** `backend/korea_news.py`, `jobs/collect_korea_preview.py`. 기존 담당 파일 `backend/news_collector.py`, `jobs/collect_news.py`, `views/news.py`를 수정했다. 팀 공동 DB와 다른 팀원 파일은 수정하지 않았다.

1. [정책브리핑 해양수산부 보도자료 목록](https://m.korea.kr/briefing/pressReleaseList.do?repCode=A00023&repCodeType=%EC%A0%95%EB%B6%80%EB%B6%80%EC%B2%98)에서 최신 20건의 제목·날짜·원문 주소를 읽는다.
2. 제목으로 해양·수산 관련성을 확인하고 기존 원문 주소와 중복되는 글을 건너뛴다. 제목 기반 필터라 관련 글을 놓치거나 무관한 글이 통과할 가능성은 있다.
3. 각 상세 페이지에 **텍스트 공공누리 제1유형** 표시가 있는지 확인한다. 표시가 없거나 본문을 안전하게 추출할 수 없으면 등록하지 않는다. [표시가 없는 남방큰돌고래 기사](https://m.korea.kr/briefing/pressReleaseView.do?gubun=pressRelease&newsId=156788327&pageIndex=1&repCode=A00023)는 제외됐다.
4. 허용된 텍스트만 저장하고 이미지·첨부파일은 저장하지 않는다. `GEMINI_API_KEY`가 없거나 AI 호출에 실패하면 첫 120자를 원문 발췌로 표시한다. 키가 있으면 새 글을 요약하고, 이전에 발췌로 등록된 글은 권리 조건을 다시 확인한 뒤 AI 요약으로 갱신한다. 실패한 글을 AI 요약으로 표시하지 않는다.

실제 첫 실행에서 최신 20건 중 **새 글 4건 등록**, 공공누리 표시가 없는 **11건 제외**, 나머지는 관련성·중복 검사로 제외됐다. 다시 실행하면 새 글 0건으로 중복 등록되지 않았다. 등록된 새 글: [해양 기술](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156787892), [남극해 협력](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156787891), [해양경제 포럼](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156787890), [부산 엑스포 동정](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156787964).

Windows 예약 작업 `SeaInfoJungKoreaNewsPreview`를 **한국 시간 매일 06:00**에 등록했다. 배터리 사용 중에도 시작하고 절전 해제를 시도하도록 설정했다. 2026-11-10 수동 실행 결과 `LastTaskResult=0`, 로그에 새 글 0건·출처 오류 0건·종료 코드 0이 기록됐다. 다음 예약 시각은 2026-11-11 06:00이다. 이 설정은 담당 PC와 로컬 미리보기 DB에만 적용되며, PC가 꺼져 있으면 정시에 실행될 수 없다. 배포 서버에는 별도로 예약 작업을 등록해야 한다.

### AI 요약 전환 준비 · 2026-11-10

**신규 담당 파일:** `backend/korea_ai.py`. 담당 작업 `jobs/collect_korea_preview.py`의 강제 Gemini 비활성화를 제거했다. 키가 설정된 뒤 실행하면 기존 발췌 기사도 기사별 제1유형 표시를 다시 확인한 뒤 AI 요약으로 바꾼다. 키 값은 문서·로그·저장소에 기록하지 않는다.

### AI 요약 실접속 결과 · 2026-11-10

사용자가 키를 로컬에 설정한 뒤 실접속했다. 기존 `.env`의 `gemini-2.5-flash`는 생성 요청에 HTTP 404를 반환했으며, 담당 미리보기 작업에서만 `gemini-3.5-flash-lite`를 사용해 정상 응답을 확인했다. 기사별 이용 조건을 다시 확인한 **해양수산부/정책브리핑 5건**(자동 수집 4건, 기존 수동 등록 1건)을 AI 2문장 요약으로 갱신했다. API와 뉴스 화면에서 `ai=true` 및 `AI 요약` 표시를 확인했다. 별도의 갯벌 기사 1건은 기존 수동 요약을 유지한다.

첫 AI 출력 중 숫자 표기가 잘못된 예가 있어 프롬프트를 200자 이내·핵심 사실 위주로 조정하고 5건을 다시 생성·확인했다. AI 요약은 향후에도 사실 오류가 생길 수 있으므로 공개 배포 시 검토 절차가 필요하다. 현재 자동 수집·요약은 담당 로컬 미리보기 DB에만 반영되며 팀 공동 DB나 배포 서버에는 반영되지 않았다.

## 남은 확인

1. 각 게시물의 공공누리 유형 또는 매체의 본문 저장·AI 요약·공개 허락을 증빙으로 확보한다.
2. 허용된 게시물은 작성 연도·기관명·원문 URL·표시된 작성자 등 필요한 출처 정보를 화면에 표시할 수 있는지 확인한다.
3. 배포 서버에 같은 기사별 검증 흐름을 연결하고 06:00 예약 실행을 별도 등록·검증한다. 공동 DB 및 배포 구성 변경은 팀 협의가 필요하다.
