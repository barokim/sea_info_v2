# Sea-Info Agent 설치 · 실행 가이드

처음 해 보는 사람도 순서대로 따라 하면 되도록 썼어요. **가장 빠른 방법은 2장의 실행 스크립트**예요. 막히면 맨 아래 **자주 나는 문제**를 보세요.

---

## 1. 한눈에 보기

```
[브라우저] ──▶ 화면 Streamlit (포트 8501)
                  │  HTTP
                  ▼
              API 서버 FastAPI (포트 8000 · 문서 /docs) ── pydantic으로 입력 · 출력 검사
                  ├─ SQLite 파일 (data/sea_info.db): 회원 · 관찰 기록 · 게시글 · 댓글 · 게시판 · 문의 · 뉴스
                  ├─ Redis (Docker, 포트 6379): 로그인 세션 · 1회용 인증 링크 값 · 하루 분석 횟수 · 랭킹 · 조회수
                  ├─ Supabase: 가입 · 로그인 · 메일 인증(링크) · 관리자 권한 (키가 없으면 SQLite로 대체)
                  ├─ Google SMTP: 인증 메일(Supabase에 연결) · 제보 알림 메일 (없으면 화면 · 로그에 링크 표시)
                  ├─ Gemini: 사진 속 생물 알아보기 · 뉴스 요약 (없으면 예시 결과)
                  └─ Jira: 제보 → 이슈 자동 생성 (없으면 '미연결'로 저장만)
```

- 키와 주소는 모두 **환경변수**로 받아요. 로컬은 `.env` 파일, 배포는 배포 사이트의 환경변수 설정 화면이에요.
- 키를 하나도 넣지 않아도 **로컬 대체 모드**로 모든 화면이 돌아가요. 키를 넣은 기능만 실제 서비스로 바뀌어요.

## 2. 가장 빠른 실행: 스크립트 한 번

### 준비물 (처음 한 번)

| 준비물 | 설명 |
|---|---|
| Windows: Python 3.13 / Mac · Linux: Python 3.10 이상 | [python.org](https://www.python.org/downloads/)에서 설치. Windows는 Python 3.13과 Python 런처를 설치하고 **“Add python.exe to PATH” 체크**. uv 사용자는 `uv python install 3.13`도 가능해요. |
| Docker Desktop | [docker.com](https://www.docker.com/products/docker-desktop/)에서 설치 후 **실행해 두기** (Redis를 켜요) |

### 실행

| 컴퓨터 | 할 일 |
|---|---|
| Windows | `sea_info` 폴더의 **`start.bat` 더블클릭** |
| Mac · Linux | 터미널에서 `sea_info` 폴더로 가서 아래 명령 |

```bash
./start.sh
```

스크립트가 이 순서로 알아서 해요. 처음에는 설치 때문에 몇 분 걸려요.

1. Python 버전 확인
2. 가상환경(`.venv`) 만들기. Windows에서는 Python 3.13을 사용하고, 기존 환경의 버전이 다르면 `.venv-backup-*`으로 백업한 뒤 다시 만들어요. 백업은 Git에서 제외돼요.
3. 필요한 프로그램 설치 (`requirements.txt`가 바뀌었을 때만 다시 설치)
4. `.env` 파일이 없으면 `.env.example`을 복사해서 만들기
5. Redis 켜기 (`docker compose up -d`)
6. API 서버 켜기 → 화면 켜기 → 브라우저가 `http://localhost:8501`로 열려요

| 끄기 | 오류 검사 (마지막 줄이 `문제 0건`이면 통과) |
|---|---|
| 화면 창에서 `Ctrl + C` 후 `stop.bat` / `./stop.sh` | `check.bat` / `./check.sh` (API 서버가 켜져 있을 때) |

### 처음 둘러보기 (로컬 대체 모드)

| 계정 | 이메일 | 비밀번호 |
|---|---|---|
| 회원 (바다탐험가) | `explorer@example.com` | `sea12345` |
| 관리자 (운영자 바다) | `admin@example.com` | `admin12345` |

- 이 시험 계정의 비밀번호는 **로컬(`APP_ENV=local`)에서만** 만들어져요. 배포(`APP_ENV=production`)하면 시험 계정으로는 로그인할 수 없고, 관리자는 `ADMIN_EMAILS`에 넣은 이메일로 가입해서 써요.
- 로그인은 새로 고침해도 풀리지 않아요. **로그인 상태 유지**를 체크하면 7일 동안, 체크하지 않으면 브라우저를 닫을 때까지 이어져요 (브라우저 쿠키 `sea_token`). 로그아웃하면 바로 지워져요.
- 로그인은 **이메일 + 비밀번호**만이에요 (코드 입력 없음).
- 새로 가입하면 **메일 인증 링크**를 보내요. 메일 속 링크를 누르면 인증이 끝나고 바로 닉네임 · 캐릭터 고르기로 넘어가요. Gmail 설정 전에는 메일 대신 **화면의 ‘개발 모드’ 상자**에 링크가 보여요. **[메일 속 링크 누르기]**를 누르면 메일 링크를 누른 것과 같아요. `logs/api.log`에도 찍혀요. 비밀번호 찾기도 같은 방식이에요.
- 왼쪽 메뉴 아래 **보기 모드**(비회원 · 회원 · 관리자)로 바로 바꿔 볼 수도 있어요. 주소 뒤에 `?as=member`, `?as=admin`도 돼요. 이 기능은 `APP_ENV=local`일 때만 보여요.
- 메뉴 아래 작은 글씨로 지금 모드가 보여요: `로그인 로컬 · 메일 개발 · AI 예시 · Jira 미연결`.
- API 문서: `http://localhost:8000/docs` 에서 모든 API를 눌러서 시험해 볼 수 있어요.

## 3. 키 넣기 (`.env`)

1. `sea_info` 폴더의 `.env` 파일을 메모장 · VS Code로 열어요. (없으면 `.env.example`을 복사해서 이름을 `.env`로)
2. 아래 표를 보고 **필요한 것만** 채워요. 비워 둔 기능은 로컬 대체 모드로 남아요.
3. 저장한 뒤 **끄고 다시 켜요** (`stop` → `start`).

> ⚠️ `.env`는 깃 · 채팅 · 메신저에 올리지 마세요(`.gitignore`에 들어 있어요). 실수로 올렸다면 그 키를 **바로 폐기하고 새로 발급**해요.

| 기능 | 넣을 변수 | 어디서 받나요 |
|---|---|---|
| 생물 알아보기 (Gemini) | `GEMINI_API_KEY` (`GEMINI_MODEL` 기본 `gemini-2.5-flash`) | Google AI Studio → API 키 만들기. 모델 이름이 오류 나면 AI Studio에서 쓸 수 있는 이름으로 바꿔요 |
| 가입 · 로그인 · 메일 인증 (Supabase) | `SUPABASE_URL`, `SUPABASE_ANON_KEY` | Supabase 프로젝트 → 프로젝트 설정의 API 화면 (Project URL, anon public 키) |
| 알림 메일 · 인증 메일 (Google SMTP) | `SMTP_USER`(Gmail 주소), `SMTP_PASSWORD`(앱 비밀번호 16자리), `MAIL_FROM`, `OPS_EMAIL`(제보 알림 받을 메일) | Google 계정 → 보안 → **2단계 인증 켜기** → **앱 비밀번호** 만들기. 계정 비밀번호가 아니에요. Supabase를 쓰면 같은 Gmail · 앱 비밀번호를 Supabase SMTP 설정에도 넣어요(아래 4번) |
| 제보 → Jira | `JIRA_BASE_URL`(예: `https://팀이름.atlassian.net`), `JIRA_EMAIL`, `JIRA_API_TOKEN`, `JIRA_PROJECT_KEY`(예: `SEA`) | Atlassian 계정 → 보안 → API 토큰 만들기. 프로젝트 키는 Jira 프로젝트 설정에 있어요 |
| 관리자 지정 | `ADMIN_EMAILS` (쉼표로 여러 명) | 이 이메일로 로그인하면 관리자 메뉴가 생겨요 |

### Supabase를 쓸 때 꼭 할 설정 (메일 링크 인증)

Supabase는 **가입 · 로그인 · 메일 인증 · 권한에만** 써요. 데이터는 SQLite에 있어요. 흐름은 이래요.

```
가입 → Supabase가 Gmail로 인증 메일 → 메일 속 [메일 인증하기] → 우리 사이트 /verify
     → 링크 속 인증값을 Supabase에 확인 → 인증 끝 + 바로 로그인 → 닉네임 · 캐릭터 고르기
```

메뉴 이름은 Supabase 화면 개편에 따라 조금 다를 수 있어요. 비슷한 이름을 찾아 주세요.

1. **Authentication → Sign In / Providers → Email**: Email 켜기, **Confirm email 켜기**.
2. **Authentication → URL Configuration**
   - Site URL: `.env`의 `PUBLIC_SITE_URL`과 똑같이 (로컬 `http://localhost:8501`, 배포 후에는 배포 주소)
   - Redirect URLs: `http://localhost:8501/verify` 추가 (배포 후 `https://배포주소/verify`도)
3. **Authentication → Emails → Templates**: 두 메일의 링크 주소를 바꿔요. **이걸 안 하면 링크를 눌러도 우리 사이트가 인증값을 받지 못해요.**
   - **Confirm signup** (가입 인증). 제목 예: `[Sea-Info Agent] 메일 인증을 해 주세요`
     ```html
     <h2>Sea-Info Agent 메일 인증</h2>
     <p>가입을 마치려면 아래 링크를 눌러 주세요.</p>
     <p><a href="{{ .SiteURL }}/verify?token_hash={{ .TokenHash }}&type=email">메일 인증하기</a></p>
     ```
   - **Reset Password** (비밀번호 찾기). 제목 예: `[Sea-Info Agent] 비밀번호 다시 정하기`
     ```html
     <h2>Sea-Info Agent 비밀번호 다시 정하기</h2>
     <p>아래 링크를 눌러 새 비밀번호를 정해 주세요. 직접 요청하지 않았다면 이 메일은 지워 주세요.</p>
     <p><a href="{{ .SiteURL }}/verify?token_hash={{ .TokenHash }}&type=recovery">비밀번호 다시 정하기</a></p>
     ```
4. **Gmail로 보내기 (Google SMTP)** — **Authentication → Emails → SMTP Settings**에서 Custom SMTP 켜기
   - Host `smtp.gmail.com` · Port `587` · Username: Gmail 주소 · Password: 앱 비밀번호 16자리 · Sender email: 같은 Gmail 주소 · Sender name: `Sea-Info Agent`
   - Supabase 기본 메일 발송은 시험용이라 보낼 수 있는 양이 아주 적어요. 팀이 함께 시험하려면 꼭 연결해 주세요.
5. 관리자: `ADMIN_EMAILS`에 넣거나, Supabase 사용자의 `app_metadata`에 `"role": "admin"`.
6. **확인**: 새 메일로 가입 → 메일의 링크 → 사이트에 “메일 인증을 마쳤어요”와 닉네임 칸이 나오면 성공이에요.
   - “메일 속 링크로 이 화면이 열렸나요?”가 나오면 3번 템플릿이 아직 기본값이에요. 이때도 Supabase 쪽 인증은 끝나서 비밀번호로 로그인은 돼요.
   - 링크가 “이미 사용했거나 시간이 지난 링크”라고 나오면 링크를 두 번 눌렀거나 시간이 지난 거예요. 로그인 화면에서 ‘인증 메일 다시 받기’를 눌러요.

### Jira를 쓸 때 꼭 확인할 것

- 이슈 종류 이름이 프로젝트와 같아야 해요. 한국어 Jira는 보통 `버그` · `작업`이에요 → `JIRA_ISSUE_TYPE_BUG=버그`, `JIRA_ISSUE_TYPE_DEFAULT=작업`.
- 제보가 오면: 사이트에 먼저 저장 → 접수번호 안내 → Jira 이슈 생성 → `OPS_EMAIL`로 알림 메일. Jira가 실패해도 제보는 남고, 관리자 ‘문의’ 화면에 실패 표시와 **[Jira 다시 보내기]**가 생겨요(같은 이슈가 두 번 생기지 않아요).
- 이슈가 끝났는지 받는 방법:
  - 로컬: 관리자 ‘문의’ 화면의 **[Jira 상태 가져오기]**
  - 배포 후: Jira 웹훅 주소를 `https://배포주소/webhooks/jira?secret=<JIRA_WEBHOOK_SECRET>`로 등록 (이슈 업데이트 이벤트)

## 4. 스크립트 없이 직접 실행 (터미널 3개)

스크립트가 안 될 때나 개발할 때 써요. 모든 명령은 `sea_info` 폴더에서 해요.

**처음 한 번: 가상환경 · 설치 · .env**

Mac · Linux

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt && cp -n .env.example .env
```

Windows (PowerShell)

```powershell
py -m venv .venv; .venv\Scripts\Activate.ps1; pip install -r requirements.txt; if (!(Test-Path .env)) { copy .env.example .env }
```

> PowerShell에서 “스크립트를 실행할 수 없습니다”가 나오면 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`를 한 번 실행해요.

**터미널 ① Redis**

```bash
docker compose up -d
```

**터미널 ② API 서버** (가상환경을 켠 상태에서. `--reload`는 코드를 고치면 자동으로 다시 켜요)

```bash
uvicorn backend.main:app --reload --port 8000
```

**터미널 ③ 화면** (가상환경을 켠 상태에서)

```bash
streamlit run app.py
```

## 5. 스마트폰에서 보기

1. 컴퓨터와 폰을 같은 와이파이에 연결해요.
2. 화면을 켤 때 터미널에 나온 `Network URL: http://192.168.x.x:8501`을 폰 브라우저에 입력해요.
3. 폰은 화면(8501)만 열면 돼요. API 서버는 화면이 컴퓨터 안에서 부르니까 폰에 열어 줄 필요가 없어요.
4. 안 열리면 컴퓨터 방화벽에서 Python을 허용해 주세요.

## 7. 배포할 때

1. 배포 사이트의 환경변수 화면에 `.env`와 **같은 이름**으로 값을 넣어요. `APP_ENV=production`으로 바꾸면 시험용 로그인 · 보기 모드 · 화면의 개발용 인증 링크가 꺼져요.
2. 실행할 것은 두 개예요: API 서버(`uvicorn backend.main:app --host 0.0.0.0 --port 8000`)와 화면(`streamlit run app.py --server.port 8501 --server.address 0.0.0.0`). 화면의 `BACKEND_URL`은 API 서버 주소로.
3. Redis는 Docker(`docker compose up -d`)나 호스팅 사이트의 Redis를 쓰고 `REDIS_URL`을 맞춰요.
4. `PUBLIC_SITE_URL`을 실제 화면 주소로, Supabase의 Site URL도 같게. Redirect URLs에 `https://배포주소/verify`를 추가해요. (메일 속 링크가 이 주소를 열어요)
5. 뉴스 자동 수집(매일 06:00)은 서버의 예약 실행에 `python jobs/collect_news.py`를 등록해요. 방법은 그 파일 맨 위 설명에 있어요.

## 8. 팀 작업 방법 (담당자별 파일)

| 담당 | 백엔드 (FastAPI) | 화면 (Streamlit) |
|---|---|---|
| 편성훈 | `backend/main.py · config.py · db.py · models.py · core/` · `routers/core.py · identify.py` | `app.py` · `components/ui.py · nav.py` · `services/api.py · db.py · ai.py` · `views/identify.py` |
| 이종민 | `routers/auth.py · admin.py` · `auth_provider.py` | `views/login.py · verify.py · mypage.py · admin/dashboard.py · posts.py · settings.py · members.py` · `services/auth.py · admin_data.py` |
| 김바로 | `routers/aquarium.py · tide.py · inquiries.py` | `views/home.py · aquarium.py · user_aquarium.py · report.py · admin/inquiries.py` · `services/aquarium_data.py · inquiry_data.py` |
| 차유진 | `routers/community.py · admin_boards.py` | `views/community.py · write.py · admin/boards.py` · `services/community_data.py` · `components/fields.py` |
| 이정민 | `routers/games.py · news.py · admin_contents.py` · `news_collector.py` | `views/playground.py · news.py · admin/contents.py` · `services/news_data.py · games_data.py` · `jobs/collect_news.py` |

1. 내 파일만 고쳐요. 공통 파일(위 표의 편성훈 칸)은 편성훈 님에게 요청해요.
2. API를 새로 만들면 요청 · 응답 모양을 pydantic 모델로 정의해요(`backend/schemas/`). 오류 문구는 한국어 해요체로.
3. 화면은 `services/` 함수만 불러요. 화면 파일에서 API 주소를 직접 쓰지 않아요.
4. 올리기 전에 `check` 스크립트로 `문제 0건`을 확인해요.
5. 문구는 기능정의서 7장(말투 · 용어 사전)을 따라요.

## 9. 자주 나는 문제

| 증상 | 해결 |
|---|---|
| `start.bat`이 바로 닫혀요 | 폴더 빈 곳에서 Shift+오른쪽 클릭 → 터미널 열기 → `start.bat` 입력해서 메시지 확인 |
| “Python 3.13을 설치해 주세요” (Windows) | Python 3.13과 런처를 설치하거나 `uv python install 3.13`을 실행해 주세요. 다른 버전의 Python만 있으면 실행되지 않아요. Mac · Linux는 Python 3.10 이상이 필요해요. |
| PyYAML 설치 중 “Microsoft Visual C++ 14.0 or greater is required” | Windows에서는 Python 3.13으로 실행해 주세요. `start.bat`이 다른 버전의 가상환경을 백업하고 다시 만들어요. |
| “Redis를 켤 수 없어요” / “Redis가 켜지지 않았어요” | Docker Desktop을 실행해 두고 다시 해요. `docker compose logs redis`로 원인 확인 |
| 화면에 “서버(FastAPI)에 연결하지 못했어요” | API 서버가 꺼져 있어요. `logs/api.log` 마지막 줄 확인 → `start`를 다시 |
| `Port 8000(8501) is already in use` | 이미 켜진 서버가 있어요. `stop` 후 다시, 또는 `API_PORT=8001 WEB_PORT=8502 ./start.sh` (Windows는 `set API_PORT=8001` 후 `start.bat`) |
| 사진을 올려도 늘 소라게 | Gemini 키가 없어서 예시 결과예요. `.env`의 `GEMINI_API_KEY` 확인 → 다시 켜기. 메뉴 아래 모드가 `AI Gemini`인지 확인 |
| “알아보지 못했어요” | `logs/api.log`의 `[Gemini 오류]` 줄 확인. 키 오타 · 모델 이름 · 인터넷 연결이 흔한 원인 |
| 인증 메일이 안 와요 | 스팸함 확인. Supabase를 쓰면 Supabase의 SMTP 설정(3장 4번), 아니면 `.env`의 `SMTP_PASSWORD`가 **앱 비밀번호**인지 확인. 개발 모드에서는 화면 · 로그에 링크가 보여요 |
| 링크를 눌렀더니 “메일 속 링크로 이 화면이 열렸나요?” | Supabase 메일 템플릿이 기본값이에요 → 3장 3번 |
| 폰에서 메일 링크를 눌렀더니 열리지 않아요 | 링크 주소가 `localhost`라서 폰에서는 열 수 없어요. 컴퓨터에서 메일을 열어 누르거나, 폰에서 눌렀다면 컴퓨터 화면의 ‘인증을 마쳤어요’를 눌러요 |
| 가입 후 로그인이 안 돼요 | 메일 속 인증 링크를 먼저 눌러야 해요. 로그인 화면에서 ‘인증 메일 다시 받기’로 새 링크를 받을 수 있어요 |
| Jira가 ‘실패’로 떠요 | 관리자 ‘문의’ 화면의 오류 내용 확인. 프로젝트 키 · 이슈 종류 이름(`버그`/`Bug`) · API 토큰이 흔한 원인. 고친 뒤 [Jira 다시 보내기] |
| 고쳤는데 화면이 그대로 | 브라우저의 **Rerun**. `services/` · `components/`를 고쳤다면 화면 서버를 다시 켜요 |
| 화면에 빨간 오류 상자 | 상자 안 맨 아래 파일 이름 · 줄 번호를 보고 그 파일 담당자에게 알려 줘요 |

## 10. 알려진 제한 (2차에 할 일)

| 항목 | 지금 | 해결 방법 |
|---|---|---|
| Supabase 계정 탈퇴 | 사이트 데이터(SQLite)는 지워지지만 Supabase 계정 자체는 남아요 (anon 키로는 지울 수 없어요) | 관리자가 Supabase 대시보드에서 지우거나, 서버에 service role 키를 따로 두고 삭제 API 추가 |
| 물때 실제 데이터 | 예시 물때(`mock/tide.json`)를 Redis에 1시간 캐시해서 보여줘요 | `.env`의 `TIDE_API_KEY`를 받고 `backend/routers/tide.py`의 `_fetch()` 안쪽만 공공 API 호출로 바꾸기 |
| 뉴스 수집 출처 | 예시 출처가 `example.com`이라 수집이 늘 ‘실패’로 기록돼요 | 관리자 ‘콘텐츠 → 수집 출처’에 이용 조건을 확인한 실제 RSS 주소 입력 |
| 제보 사진 첨부 | 사진 고르는 칸은 보이지만 서버로 보내지 않아요 | 제보 API를 사진 업로드 방식으로 확장 (`Inquiry.photo_path` 칸은 준비돼 있어요) |
| 소셜 로그인 · 포인트 · 등급 · 답글 | 버튼만 있고 ‘2차’로 표시돼요 | 2차 개발 |
