## 2. 진행 순서

1. **분석**: 화면별 상세기능정의서 v2.5(21쪽)와 4인 업무 배정표를 사용자 입장에서 따라가며 어색한 곳 18군데를 찾았어요.
2. **초안 v0.1**: 타겟 · 개선안 · 메뉴 구조 · 플로우 · 목업 · 화면별 기능 · 톤앤매너 · 개발 가이드를 한 문서로. 질문 4개.
3. **결정 반영 v0.2**: 핵심 흐름, 주타겟, 5인 역할(편성훈 리드), 1차 범위를 확정.
4. **Streamlit 시안**: 예시 데이터로 화면 28개를 만들고, 1단계 와이어프레임 · 2단계 디자인 · 3단계 클릭 흐름을 캡처해 기획서로 묶었어요.
5. **반응형 · 실행 가이드**: 4가지 화면 폭으로 캡처하고 겹침 · 여백 문제를 고쳤어요.
6. **강사님 기술 기준 반영 v0.3**: FastAPI · pydantic · Redis · SQLite · Supabase(권한만) · Google SMTP · 환경변수 · Jira로 실제 동작하는 백엔드를 만들고, 화면을 모두 API로 옮겼어요. 실행 스크립트와 설치 가이드를 썼어요.
7. **여기서 실행해 보고 고침**: 새로 고침 로그아웃 문제 · 로그인 상태 유지 연결, 홈 배너 버튼이 붙어 보이던 것과 사진 올리기 화면 배치를 고쳤어요.
8. **메일 인증을 링크 방식으로 v0.4**: 6자리 코드를 없애고 ‘메일 속 링크를 누르면 인증 끝’으로 바꿨어요(Supabase가 보낸 인증값을 우리 /verify 화면이 확인). 로그인은 비밀번호만, 비밀번호 찾기도 링크로.

## 5. 어색했던 흐름 → 바꾼 것 (18곳)

- **핵심 흐름**: 게시해야만 수족관 저장 → 먼저 담기 · 공유는 선택 / 관찰 글 게시판 직접 선택 → ‘관찰 이야기’ 자동 / 결과 화면의 위치 입력 → 담기 단계로 / 사진 고르는 곳 3개 → 1개 / 안전 정보 없음 → ‘괜찮아요 · 조심해요 · 만지지 마세요’ 배지(참고용) / 늦은 로그인 → 담기 누를 때 안내 + 결과 보관
- **메뉴 · 이동**: 홈 메뉴 추가 / 커뮤니티 첫 탭 ‘관찰 이야기’ / 오른쪽 위 ‘내 정보’ / 제보·건의는 ‘도움’ 묶음으로 / ‘목록으로’는 들어온 곳으로 / 물때 첫 화면 빈칸 → 기본 지역 + ‘관찰하기 좋은 시간’
- **말과 설정**: 용어 통일(용어 사전) / 공개 설정 4곳 → 3개(공유 여부 · 위치 공개 · 수족관 공개) / 게임 비회원 처리 정의
- **진행 방식**: 추첨 배정 → 흐름 단위 배정 / 무거운 기능 범위 결정 / 공통 틀 담당 지정

## 7. 기술 구성

```
[브라우저] ─▶ Streamlit 화면 (8501)
                │  services/api.py (HTTP + 로그인 토큰)
                ▼
            FastAPI (8000, /docs) ── pydantic 검사 · 권한 확인
                ├─ SQLite  data/sea_info.db   회원 · 관찰 기록 · 게시글 · 댓글 · 게시판 · 문의 · 뉴스 · 설정
                ├─ Redis   (Docker)           세션 · 1회용 인증 링크 값 · 분석 횟수 · 랭킹 · 조회수 · 임시 보관
                ├─ Supabase                    가입 · 로그인 · 메일 링크 인증 · 권한
                ├─ Google SMTP                 인증 메일(Supabase에 연결) · 제보 알림 · 처리 결과 메일
                ├─ Gemini                      생물 알아보기 · 뉴스 요약
                └─ Jira                        제보 → 이슈, 완료 → 웹훅
```

- **로컬 대체 모드**: 키가 비어 있으면 그 기능만 대체돼요. 로그인은 SQLite(시험 계정 제공), 메일은 화면 · 로그에 인증 링크 표시, 분석은 예시 결과, Jira는 ‘미연결’로 저장만.
- **한 번에 저장**: 수족관 담기 + 공유는 서버에서 한 번의 저장으로 처리해요. 하나라도 실패하면 둘 다 저장되지 않아요.
- **제보 → Jira**: 저장 → 접수번호 → Jira 이슈(오류 제보 = 버그, 나머지 = 작업) → 담당 메일. 실패해도 제보는 남고 [다시 보내기](중복 생성 없음). 완료는 웹훅 또는 [상태 가져오기].

### 실행해 보다가 찾아 고친 것

- **새로 고침하면 로그아웃되던 문제**: 로그인 정보가 화면 세션에만 있어서 새로 고침하면 사라졌어요. 이제 브라우저 쿠키에 로그인 토큰을 두고 다시 열 때 이어 붙여요 (`services/auth.py`의 `restore_from_cookie` · `flush_cookie`, `app.py`).
- **‘로그인 상태 유지’ 체크박스가 아무 데도 연결되지 않던 문제**: 체크하면 7일, 안 하면 브라우저를 닫을 때까지 유지돼요.
- **홈 배너의 ‘사진으로 알아보기’ 버튼이 배너에 딱 붙어 보이던 문제**: 버튼을 배너 안으로 넣고, 3단계 안내를 번호 띠로, 예시 버튼 간격을 넓혔어요 (휴대폰 · 태블릿 · PC 확인).

## 11. 남은 일 · 확인 필요

- **실제 키로는 아직 시험하지 않았어요**: Gemini · Supabase · Gmail · Jira. 친구가 `.env`에 키를 넣고 처음 실행할 때 각 기능을 한 번씩 확인해 주세요. 키는 채팅에 붙여 넣지 않아요.
- **`start.bat`은 Windows에서 직접 실행해 보지 못했어요**: 처음 실행할 때 화면 메시지를 확인해 주세요. 막히면 설치 가이드 4장(직접 실행)으로 할 수 있어요.
- **Gemini 모델 이름**: 기본값 `gemini-2.5-flash`가 지금도 쓸 수 있는지 Google AI Studio에서 확인.
- **Jira 이슈 종류 이름**: 한국어 Jira면 `버그` · `작업`으로 `.env` 설정.
- **물때 실제 데이터 출처, 뉴스 수집 출처(이용 조건), 배포할 사이트**: 정해지면 반영.
- **Supabase 대시보드 설정**: 메일 템플릿 2개(가입 인증 · 비밀번호 재설정)의 링크 주소, Gmail SMTP 연결, Site URL · Redirect URLs를 실제 프로젝트에서 한 번 확인해 주세요 (설치 가이드 3장). 여기서는 가짜 Supabase로만 시험했어요.
- **알려진 제한**: Supabase 계정 탈퇴, 제보 사진 첨부, 소셜 로그인 · 포인트 · 답글 → 설치 가이드 10장.
